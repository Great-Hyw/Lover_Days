## 一、全局约定

### 1.1 基础信息

| 项目 | 值 |
| --- | --- |
| 接口前缀 | 所有路径以 `/api` 开头（开发环境由 Vite 代理到后端 `http://localhost:8080`） |
| 请求超时 | 前端 10 秒超时，后端应在 10s 内响应 |
| 传输安全 | 生产环境必须 HTTPS（凭据明文在请求体中传输） |
| 字段命名 | JSON 一律 **camelCase**（如 `isYearly`、`bgImage`、`createdAt`）；数据库列名可用 snake_case，由后端做映射 |
| 时间格式 | 日期 `YYYY-MM-DD`；时间戳字段 ISO 8601 字符串（如 `2026-10-03T08:30:00.000Z`），建议统一 UTC 或带时区 |

### 1.2 统一响应包络

所有接口（含错误）返回 JSON：

```json
// 成功
{ "code": 0, "message": "success", "data": <业务数据，见各接口> }

// 失败（HTTP 状态码与 code 保持一致）
{ "code": 400, "message": "用户名或密码错误" }
```

- 前端拦截器：`code === 0` → 把 `data` 交给业务代码；`code !== 0` → 抛出 `Error(message)`，页面用 toast 展示 message。
- **message 是给用户看的中文文案**，后端直接返回面向用户的提示，前端原样展示。
- HTTP 状态码建议与 code 一致（200/201/400/401/404/500）；前端接受任意 2xx。

### 1.3 鉴权机制

| 项目 | 约定 |
| --- | --- |
| 方式 | `Authorization: Bearer <token>` 请求头 |
| token 签发 | 登录 / 注册成功时返回；前端原样透传，不做解析 |
| 有效期 | **30 分钟**。前端将其存于 Cookie（`Max-Age=1800`），到期浏览器自动删除；后端会话有效期应与之对齐，过期后所有需鉴权接口返回 401 |
| 用户隔离 | **前端不传 user_id**。后端必须从 token 解析当前用户，所有业务数据按 user_id 隔离 |
| 无效 token | 返回 HTTP 401 + `{ "code": 401, "message": "未登录或登录已过期" }` |

**前端对 401 的自动行为**（后端设计需知晓）：
应用启动时前端会调 `GET /auth/profile` 校验本地 token（存于 Cookie），任何失败（含 401）→ 前端自动清除 Cookie 中的 token 与用户缓存 → 路由守卫将页面重定向到登录页。**后端无需处理登出跳转逻辑。**

### 1.4 前端错误处理总表

| 后端返回 | 前端行为 |
| --- | --- |
| 2xx + code=0 | 正常渲染 data |
| 任意响应 code≠0 | toast 展示 message |
| HTTP 401 | 自动清除登录态并跳回登录页（见 1.3） |
| 网络不通 / 超时 / 5xx | toast 提示失败，页面保留用户输入 |

## 二、数据库设计建议

共 5 张表。id 类型前端不敏感（number / string 均可），推荐 UUID 或自增。

### 2.1 users —— 用户表

| 列 | 类型建议 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | UUID / BIGINT | PK | 用户主键 |
| username | VARCHAR(50) | NOT NULL, **UNIQUE**, 索引 | 用户名，唯一 |
| password_hash | VARCHAR(255) | NOT NULL | **只存哈希**（scrypt / bcrypt），绝不存明文 |
| nickname | VARCHAR(50) | NOT NULL | 昵称，注册未填时取 username |
| avatar | VARCHAR(500) | NOT NULL DEFAULT '' | 头像 URL |
| created_at | TIMESTAMP | NOT NULL | |
| updated_at | TIMESTAMP | NOT NULL | |

> 响应中**永远不返回** password_hash。密码只出现在登录/注册请求体中（见 3.1/3.2），仅用于传输校验。

### 2.2 sessions —— 会话表（若用无状态 JWT 可省略）

| 列 | 类型建议 | 约束 |
| --- | --- | --- |
| token | VARCHAR(128) | PK（随机 64 位十六进制及以上强度） |
| user_id | 同 users.id | FK → users.id, NOT NULL |
| expires_at | TIMESTAMP | NOT NULL，与前端 Cookie 一致：**30 分钟** |
| created_at | TIMESTAMP | NOT NULL |

### 2.3 anniversaries —— 纪念日表

| 列 | 类型建议 | 约束 | 说明 |
| --- | --- | --- | --- |
| id | UUID / BIGINT | PK | |
| user_id | 同 users.id | FK, NOT NULL, 索引 | 归属用户，从 token 解析 |
| title | VARCHAR(20) | NOT NULL | 名称，≤20 字（与前端 maxlength 一致） |
| date | DATE | NOT NULL | `YYYY-MM-DD`，**不得晚于当天** |
| type | VARCHAR(16) | NOT NULL | 枚举：love/meet/proposal/birthday/festival/travel/gift/custom |
| icon | VARCHAR(16) | NOT NULL DEFAULT '⭐' | emoji |
| color | CHAR(7) | NOT NULL DEFAULT '#ff6b9d' | 格式 `#RRGGBB` |
| is_yearly | BOOLEAN | NOT NULL DEFAULT FALSE | 是否每年重复 |
| note | VARCHAR(120) | NOT NULL DEFAULT '' | 备注，≤120 字 |
| bg_image | VARCHAR(500) | NOT NULL DEFAULT '' | 背景图 URL（指向 photos.key 对应的访问地址） |
| created_at / updated_at | TIMESTAMP | NOT NULL | |

### 2.4 photos —— 相册图片表

| 列 | 类型建议 | 约束 | 说明 |
| --- | --- | --- | --- |
| key | VARCHAR(255) | PK | 对象存储 key，如 `anniversary/{userId}/{时间戳}-{文件名}`；含 `/`，可作 URL 参数 |
| user_id | 同 users.id | FK, NOT NULL, 索引 | |
| url | VARCHAR(1000) | NOT NULL | 访问地址（建议 OSS/CDN 地址） |
| name | VARCHAR(255) | NOT NULL | 原始文件名 |
| size | BIGINT | NOT NULL | 字节数 |
| created_at | TIMESTAMP | NOT NULL | 上传时间，倒序展示用 |

> Mock 版「最多 12 张」是浏览器本地限制，后端可自定义配额或不限。

### 2.5 preferences —— 用户偏好表

| 列 | 类型建议 | 约束 |
| --- | --- | --- |
| user_id | 同 users.id | PK, FK → users.id |
| main_anniversary_id | 同 anniversaries.id | NULLABLE, FK；NULL = 未设置 |
| updated_at | TIMESTAMP | NOT NULL |

## 三、接口明细

### 3.1 登录 `POST /api/auth/login`

无需鉴权。

**请求体**：

| 字段 | 类型 | 必填 | 格式与校验 |
| --- | --- | :---: | --- |
| username | string | 是 | trim 后非空；长度 ≥2（前端已预校验，后端必须复验） |
| password | string | 是 | 非空；长度 ≥6（前端已预校验，后端必须复验） |

```json
{ "username": "lover", "password": "123456" }
```

**成功** 200，`data`：

```json
{
  "token": "2eaa168a0ab5f6a9…（64位十六进制或等强度）",
  "user": { "id": "u-001", "username": "lover", "nickname": "甜甜", "avatar": "" }
}
```

**失败**：

| HTTP/code | message | 触发条件 |
| --- | --- | --- |
| 400 | 请输入用户名和密码 | 字段缺失或空 |
| 400 | 用户名或密码错误 | 用户不存在或哈希不匹配（**不区分两种情况**，防用户名枚举） |

### 3.2 注册 `POST /api/auth/register`

无需鉴权。成功即返回 token（前端自动进入登录态，不再调 3.1）。

**请求体**：

| 字段 | 类型 | 必填 | 格式与校验 |
| --- | --- | :---: | --- |
| username | string | 是 | trim 后非空；长度 ≥2；**全局唯一** |
| password | string | 是 | 长度 ≥6；后端哈希后入库 |
| nickname | string | 否 | 非空时 ≤50 字；缺省取 username |

```json
{ "username": "newuser", "password": "123456", "nickname": "昵称" }
```

**成功** **201**，`data`：同 3.1 的 LoginResult。

**失败**：

| HTTP/code | message | 触发条件 |
| --- | --- | --- |
| 400 | 请输入用户名和密码 | 必填字段缺失 |
| 400 | 用户名至少 2 个字符 | username 长度 <2 |
| 400 | 密码至少 6 位 | password 长度 <6 |
| 400 | 用户名已存在 | username 唯一约束冲突 |

### 3.3 获取当前用户 `GET /api/auth/profile`

需要鉴权。无请求参数。

**成功** 200，`data`：

```json
{ "id": "u-001", "username": "lover", "nickname": "甜甜", "avatar": "" }
```

**失败** 401：`未登录或登录已过期`（token 缺失/无效/过期）。

### 3.4 纪念日模块 —— 地址与数据模型（务必先读）

#### 3.4.0 端口与路径映射（最容易出错的地方）

| 环节 | 地址 |
| --- | --- |
| 后端服务地址（开发） | `http://localhost:8080` |
| 前端发出的请求 | `http://localhost:5173/api/anniversaries`（axios 的 baseURL 固定为 `/api`） |
| Vite 代理动作 | 剥掉 `/api` 前缀后转发（`vite.config.js` 中 `rewrite: path => path.replace(/^\/api/, '')`） |
| **后端 Controller 实际收到** | `http://localhost:8080/anniversaries`（**无 /api 前缀**） |

即后端 `@RequestMapping` 直接写 `"/anniversaries"`，**不要**带 `/api`。映射示意：

```
前端 GET  /api/anniversaries        ──代理剥前缀──▶  后端 GET  /anniversaries
前端 POST /api/anniversaries        ──代理剥前缀──▶  后端 POST /anniversaries
前端 PUT  /api/anniversaries/123    ──代理剥前缀──▶  后端 PUT  /anniversaries/123
```

> 生产环境没有 Vite，由 Nginx 等反向代理完成同样的前缀剥离（或后端自行加上 `/api` 上下文，二选一，全项目保持一致即可）。

五个接口速查（路径均指**后端实际路径**；前端 URL 一律在前面加 `/api`）：

| # | 方法 | 后端路径 | 鉴权 | 用途 |
| --- | --- | --- | :---: | --- |
| 3.4.1 | GET | `/anniversaries` | 是 | 查询当前用户全部纪念日 |
| 3.4.2 | GET | `/anniversaries/{id}` | 是 | 查询单个纪念日详情 |
| 3.4.3 | POST | `/anniversaries` | 是 | 新建纪念日 |
| 3.4.4 | PUT | `/anniversaries/{id}` | 是 | 更新纪念日（**部分更新**，含设置背景图） |
| 3.4.5 | DELETE | `/anniversaries/{id}` | 是 | 删除纪念日 |

#### 3.4.A Anniversary 对象字段总表（列表/详情/新建/更新的返回值都是它）

| 字段 | 类型 | 是否必有 | 含义 | 示例 |
| --- | --- | :---: | --- | --- |
| `id` | number 或 string | 返回时必有 | 主键，前端只做透传和字符串比较（`String(id)`），number/string 均可 | `1716000001` |
| `title` | string | 必有 | 纪念日名称，1–20 字 | `"我们在一起啦"` |
| `date` | string | 必有 | 纪念日日期，格式严格 `YYYY-MM-DD` | `"2023-10-01"` |
| `type` | string | 必有 | 类型枚举，仅允许以下 **8** 个值：`love`(相恋日)、`meet`(相识日)、`proposal`(求婚日)、`birthday`(生日)、`festival`(节日)、`travel`(旅行)、`gift`(礼物)、`custom`(自定义) | `"love"` |
| `icon` | string | 必有 | 一个 emoji 字符，作为列表/卡片图标 | `"💖"` |
| `color` | string | 必有 | 主题色，`#RRGGBB` 六位十六进制 | `"#ff6b9d"` |
| `isYearly` | boolean | 必有 | 是否每年重复（用于周年倒计时）；前端新建时总会显式传该字段 | `true` |
| `note` | string | 必有 | 备注，0–120 字，无备注时为 `""`（不是 null） | `""` |
| `bgImage` | string | 必有 | 背景图 URL；无自定义背景时为 `""`，前端据此回退到默认粉色渐变 | `""` |
| `createdAt` | string(ISO 时间) | 返回时必有 | 创建时间，ISO 8601 | `"2026-10-03T02:00:00.000Z"` |
| `updatedAt` | string(ISO 时间) | 返回时必有 | 最后更新时间，ISO 8601 | `"2026-10-03T02:00:00.000Z"` |

> 注意：返回值中**不应出现** `userId`、`password` 等内部字段；数据归属由后端凭 token 自行判断。
> `id`、`createdAt`、`updatedAt` 一律由服务端生成，前端请求体中即使误传，后端也应忽略。

完整对象示例：

```json
{
  "id": 1716000001,
  "title": "我们在一起啦",
  "date": "2023-10-01",
  "type": "love",
  "icon": "💖",
  "color": "#ff6b9d",
  "isYearly": true,
  "note": "",
  "bgImage": "",
  "createdAt": "2026-10-03T02:00:00.000Z",
  "updatedAt": "2026-10-03T02:00:00.000Z"
}
```

#### 3.4.1 查询列表 `GET /anniversaries`

- **鉴权**：需要。从 token 解析用户，**只返回该用户自己的数据**。
- **请求参数**：无（无 query、无请求体）。当前不分页，全量返回。
- **成功响应** `200`，外层包络的 `data` 为 Anniversary 数组，**按 `date` 升序**（最早的日期在前）；无数据时返回空数组 `[]`（不是 null）：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    { "id": 1716000001, "title": "我们在一起啦", "date": "2023-10-01", "type": "love", "icon": "💖", "color": "#ff6b9d", "isYearly": true, "note": "", "bgImage": "", "createdAt": "2026-10-03T02:00:00.000Z", "updatedAt": "2026-10-03T02:00:00.000Z" },
    { "id": 1716000002, "title": "Ta 的生日", "date": "2023-12-25", "type": "birthday", "icon": "🎂", "color": "#ffa07a", "isYearly": true, "note": "记得准备惊喜", "bgImage": "", "createdAt": "2026-10-03T02:05:00.000Z", "updatedAt": "2026-10-03T02:05:00.000Z" }
  ]
}
```

- **失败**：`401`（未登录/token 失效）。

#### 3.4.2 查询详情 `GET /anniversaries/{id}`

- **路径参数**：`id` —— 纪念日主键（number 或 string，原样接收即可）。
- **请求体**：无。
- **成功响应** `200`，`data` 为单个 Anniversary 对象（结构同 3.4.A）。
- **失败**：

| HTTP/code | message | 触发条件 |
| --- | --- | --- |
| 401 | 未登录或登录已过期 | 无有效 token |
| 404 | 纪念日不存在 | id 不存在，**或该条数据属于其他用户**（不暴露归属差异） |

#### 3.4.3 新建纪念日 `POST /anniversaries`

- **鉴权**：需要（userId 从 token 取，**不要**从请求体取）。
- **请求体**（`Content-Type: application/json`），前端「添加纪念日」表单实际提交 **7 个字段**：

| 字段 | 类型 | 前端是否必传 | 后端校验/缺省规则 |
| --- | --- | :---: | --- |
| `title` | string | 是 | trim 后 1–20 字，不能为空 |
| `date` | string | 是 | 严格 `YYYY-MM-DD` 且为真实日历日期（拒绝 2 月 30 日），不晚于当天 |
| `type` | string | 是 | 必须是 8 个枚举值之一 |
| `icon` | string | 是（总有值） | 建议按 1–4 字符 emoji 接收；缺省可给 `"⭐"` |
| `color` | string | 是（总有值） | 匹配 `/^#[0-9a-fA-F]{6}$/`；缺省 `"#ff6b9d"` |
| `isYearly` | boolean | 是（总有值） | 仅接受布尔；缺省建议 `false` |
| `note` | string | 是（无内容传 `""`） | 0–120 字；缺省 `""` |

> **此接口不传 `bgImage`**：新建时背景固定为空串，背景图只能在详情页通过 3.4.4 设置。
> `id` / `createdAt` / `updatedAt` / `userId` 由服务端生成。

请求示例：

```bash
curl -X POST http://localhost:8080/anniversaries \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"title":"第一次见面","date":"2023-05-20","type":"meet","icon":"👫","color":"#ff8fab","isYearly":true,"note":"在图书馆"}'
```

- **成功响应** `201`（或 200，前端都接受），`data` 为**创建后的完整 Anniversary 对象**（必须包含服务端生成的 `id`、`createdAt`、`updatedAt`，以及补齐的 `bgImage: ""`）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "id": 1716000003,
    "title": "第一次见面",
    "date": "2023-05-20",
    "type": "meet",
    "icon": "👫",
    "color": "#ff8fab",
    "isYearly": true,
    "note": "在图书馆",
    "bgImage": "",
    "createdAt": "2026-10-08T01:00:00.000Z",
    "updatedAt": "2026-10-08T01:00:00.000Z"
  }
}
```

- **失败**：

| HTTP/code | message 示例 | 触发条件 |
| --- | --- | --- |
| 400 | 请填写纪念日名称 | title 缺失或全空白 |
| 400 | 请选择日期 | date 缺失 |
| 400 | 日期无效 | 格式错误或不存在的日历日期 |
| 400 | 日期不能晚于今天 | date > 当天 |
| 400 | 类型不合法 | type 不在枚举内 |
| 401 | 未登录或登录已过期 | 无有效 token |

#### 3.4.4 更新纪念日 `PUT /anniversaries/{id}`（部分更新）

- **路径参数**：`id`。
- **请求体**：Anniversary 字段的**任意子集**，只传需要修改的字段；**未传的字段必须保持原值不变**（这是硬性要求——前端在两种场景调用本接口）：
  1. **编辑表单保存**：传 7 个表单字段 `{title, date, type, icon, color, isYearly, note}`（不含 bgImage，此时背景图不能被清空）；
  2. **详情页设置/更换/清除背景图**：**只传一个字段** `{"bgImage": "https://…/a.png"}` 或 `{"bgImage": ""}`（此时其他字段一个都不会传，不能被误清空）。

请求示例（设置背景图）：

```bash
curl -X PUT http://localhost:8080/anniversaries/1716000003 \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"bgImage":"https://cdn.example.com/anniversary/u-001/1717000000-a.png"}'
```

- **成功响应** `200`，`data` 为**更新后的完整 Anniversary 对象**（所有字段都要返回，不是只返回改动字段），并刷新 `updatedAt`。
- **失败**：`400`（字段校验同 3.4.3）、`401`、`404 纪念日不存在`（含资源属于他人）。

#### 3.4.5 删除纪念日 `DELETE /anniversaries/{id}`

- **路径参数**：`id`。**请求体**：无。
- **成功响应** `200`，`data` 为 `null`：

```json
{ "code": 0, "message": "success", "data": null }
```

- **失败**：`401`、`404 纪念日不存在`（含资源属于他人）。删除为幂等语义亦可（重复删除返回 200），前端均能处理。

### 3.9 上传图片 `POST /api/upload`

#### 3.9.0 端口与路径映射

| 环节 | 地址 |
| --- | --- |
| 后端服务地址（开发） | `http://localhost:8080` |
| 前端发出的请求 | `POST http://localhost:5173/api/upload`（axios baseURL 固定为 `/api`） |
| Vite 代理动作 | 剥掉 `/api` 前缀后转发（`vite.config.js` 中 `rewrite: path => path.replace(/^\/api/, '')`） |
| **后端 Controller 实际收到** | `POST http://localhost:8080/upload`（**无 /api 前缀**） |

> 后端 `@RequestMapping` 直接写 `"/upload"`，**不要**带 `/api`，与 3.4 纪念日模块保持一致。

#### 3.9.1 鉴权与请求头

- **鉴权**：需要。`Authorization: Bearer <token>` 由前端拦截器自动加，userId 从 token 解析，**不要**从请求体或参数取。
- **Content-Type**：`multipart/form-data; boundary=...`，**由浏览器自动生成 boundary**，前端代码中显式写了 `multipart/form-data` 但 axios 会自动补 boundary，**后端不要校验 boundary**。

#### 3.9.2 请求体（multipart/form-data）

表单字段：

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `file` | binary（文件流） | 是 | 单文件上传；字段名严格为 `file`，**不可改为 `image`、`avatar` 等** |
| `anniversaryId` | number \| string | 否 | 图片所属纪念日的 id（前端从编辑路由取）。仅用于后端**记录图片来源**（如按纪念日聚合、删除纪念日时联动清理图片）；**后端不得因该字段自动修改纪念日的 bgImage**——设置背景仍是前端随后单独调 `PUT /anniversaries/:id`（见 3.9.6 两步流程） |

前端上传前已校验（后端必须复验）：

| 规则 | 值 |
| --- | --- |
| 允许 MIME 类型 | `image/jpeg`、`image/png`、`image/webp`、`image/gif`（白名单，非黑名单） |
| 大小上限 | 8 MB（8 × 1024 × 1024 字节，含 multipart 协议头开销） |
| 文件内容 | 后端建议做图片内容嗅探（防伪造 MIME），如读前几字节判断魔数 |

#### 3.9.3 完整请求示例

```bash
curl -X POST http://localhost:8080/upload \
  -H "Authorization: Bearer 2eaa168a0ab5f6a9..." \
  -F "file=@/path/to/love.png;type=image/png" \
  -F "anniversaryId=12"
```

#### 3.9.4 成功响应

HTTP **201**（或 200，前端均接受），统一包络。**`data` 为 Photo 实体（camelCase，但不含 `id`**——图片 id 以 3.10 列表接口返回为准）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "key": "anniversary/u-001/1717000000-a.png",
    "userId": 1,
    "url": "https://cdn.example.com/anniversary/u-001/1717000000-a.png",
    "name": "love.png",
    "size": 10240,
    "createdAt": "2026-10-11"
  }
}
```

字段说明（后端实际返回，Java 类型 → JSON）：

| 字段 | Java 类型 | JSON 类型 | 必有 | 含义 |
| --- | --- | --- | :---: | --- |
| `key` | String | string | 是 | 对象存储 key（如 OSS 对象 key），含 `/`；对应数据库列 `_key` |
| `userId` | Integer | number | 是 | 所属用户 id（从 token 解析写入，前端不回传）；对应列 `user_id` |
| `url` | String | string | 是 | 可公开（或带签名）访问的图片地址；前端会直接塞入纪念日 `bgImage` 字段并显示为 CSS 背景图，必须可被 `<img>`/CSS 加载 |
| `name` | String | string | 是 | 原始文件名 |
| `size` | Long | number | 是 | 字节数 |
| `createdAt` | LocalDate | string | 是 | 上传日期，格式 `YYYY-MM-DD`（LocalDate 无时间部分；如需精确到时分秒请改用 LocalDateTime 并同步告知前端） |
| ~~`id`~~ | — | — | 否 | **上传响应不含 id**。图片记录 id 仅由 3.10 `GET /photos` 列表返回，前端分页游标只依赖列表接口 |

> **字段命名**：后端 JSON 已是 camelCase（Jackson 默认），前端直接使用。前端 API 层（`src/api/upload.js` 的 `normalizePhoto`）额外兼容 snake_case（`_key`/`user_id`/`created_at`）写法作为兜底，后端无需任何转换。
>
> **删除接口注意**：前端 3.11 删除时请求体字段名为 `{ "key": "<key 的值>" }`，与 Photo 实体的 `key` 字段同名。

建议后端采用阿里云 OSS / 阿里云相册：
- key 规则：`anniversary/{userId}/{时间戳}-{随机串}.{ext}`
- url 建议走 CDN 域名；私有 Bucket 可返回带签名 URL（注意有效期需 ≥ 30 分钟，与 token 一致或更长）
- 同时在 `photos` 表（见 2.4）写一条记录，供 3.10 列举

#### 3.9.5 失败响应

| HTTP / code | message | 触发条件 |
| --- | --- | --- |
| 400 | 缺少上传文件 | multipart 中无 `file` 字段 |
| 400 | 仅支持图片文件 | MIME 不在白名单 |
| 400 | 图片不能超过 8MB | size > 8MB |
| 401 | 未登录或登录已过期 | token 缺失/无效/过期 |
| 500 | 服务器内部错误 | OSS 上传失败等异常 |

> 前端支持 `onUploadProgress`，后端正常响应即可，无特殊要求。

#### 3.9.6 与纪念日 bgImage 的协同流程（重要）

上传图片本身**不会**改变纪念日数据，需分两步完成「设置背景图」：

```
1. POST /upload           → 拿到 { url, key }（不含 id）
2. PUT /anniversaries/:id  → body: { "bgImage": url }（部分更新，见 3.4.4）
```

前端调用方在 `uploadImage()` 拿到 `url` 后，应立即调用 `updateAnniversary(id, { bgImage: url })` 写入纪念日。**后端不要**在 upload 接口里偷偷改纪念日表——上传与更新是独立的两步，便于复用（同一张图可被多个纪念日引用）。

### 3.10 相册列表 `GET /api/photos`

#### 3.10.1 端口与路径映射

| 环节 | 地址 |
| --- | --- |
| 前端发出的请求（首页） | `GET http://localhost:5173/api/photos` |
| 前端发出的请求（续拉） | `GET http://localhost:5173/api/photos?lastId=1024` |
| Vite 代理动作 | 剥掉 `/api` 前缀后转发 |
| **后端 Controller 实际收到** | `GET http://localhost:8080/photos?lastId=1024`（**无 /api 前缀**） |

#### 3.10.2 鉴权与查询参数

- **鉴权**：需要。从 token 解析 userId，**只返回该用户的图片**。
- **分页方式**：keyset（游标即图片 id），**每页固定 20 条，前端不传 limit/cursor**。
- **查询参数**（query string）：

| 参数 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | :---: | --- | --- |
| `lastId` | number \| string | 否 | 空 | 当前列表**最后一张图片的 id**；不传 = 第一页（取最新 20 条），传了 = 返回 `id < lastId` 的下一页 |

后端 SQL 示意：`WHERE user_id=? AND id < :lastId ORDER BY id DESC LIMIT 20`（首页省略 `id <` 条件）。

#### 3.10.3 成功响应

HTTP **200**，**必须用统一包络**，`list` 与 `hasMore` 放在 `data` **里面**（不是顶层）：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [
      {
        "id": 1025,
        "key": "anniversary/u-001/1717000000-a.png",
        "userId": 1,
        "url": "https://cdn.example.com/anniversary/u-001/1717000000-a.png",
        "name": "a.png",
        "size": 10240,
        "createdAt": "2026-10-11"
      },
      {
        "id": 1024,
        "key": "anniversary/u-001/1717000001-b.jpg",
        "userId": 1,
        "url": "https://cdn.example.com/anniversary/u-001/1717000001-b.jpg",
        "name": "b.jpg",
        "size": 20480,
        "createdAt": "2026-10-11"
      }
    ],
    "hasMore": true
  }
}
```

字段说明（行字段定义同 3.9.4）：

| 字段 | 类型 | 必有 | 含义 |
| --- | --- | :---: | --- |
| `data.list` | CloudPhoto[] | 是 | 图片数组，**按 id 倒序**（最新在上）；无图片时为 `[]`（不是 null） |
| `data.hasMore` | **boolean** | **是** | 是否还有更早的一页；**前端「加载更多」按钮的显示/隐藏完全由它驱动**，缺失或恒为 false 时按钮永不出现 |
| `data.list[].id` | number | **是** | 图片记录 id，**续拉时作为 lastId 原样回传**；⚠️ 与上传接口不同，**列表行必须返回 id**，否则前端无游标可用 |
| `data.list[].key` | string | 是 | OSS 对象 key，含 `/`，用于 3.11 删除 |
| `data.list[].userId` | number | 是 | 所属用户 id |
| `data.list[].url` | string | 是 | 可访问地址 |
| `data.list[].name` | string | 是 | 原始文件名 |
| `data.list[].size` | number | 是 | 字节数 |
| `data.list[].createdAt` | string | 是 | 上传日期 `YYYY-MM-DD` |

前端交互：首页不带 `lastId` → 渲染 20 条；点「加载更多」时把当前列表最后一项的 `id` 作为 `lastId` 续拉，结果**追加**到列表末尾；`hasMore=false` 时隐藏按钮。

#### 3.10.4 hasMore 判定算法（必须实现）

**多查 1 条**判断有没有下一页，避免 `count(*)`，单条 SQL 搞定：

```
rows    = SELECT ... WHERE user_id = ? [AND id < lastId] ORDER BY id DESC LIMIT 21
hasMore = (rows.length > 20)
if hasMore: rows = rows[0 : 20]        // 丢掉第 21 条，只回 20 条
return { list: rows, hasMore }
```

- 总数 ≤ 20 → `hasMore=false`，按钮不出现（**这是正确行为**，不是 bug）
- 照片超过 20 张时后端必须返回 `hasMore=true`，否则按钮永远出不来

#### 3.10.5 后端完整参考实现（Spring Boot + MyBatis）

**Controller**（`PhotoController.java`）：

```java
@GetMapping("/photos")
public Result getPhotos(@RequestParam(value = "lastId", required = false) Integer lastId,
                        HttpServletRequest request) {
    // userId 从 token 解析（与你的鉴权拦截器同一套逻辑），只查本用户的图
    Integer userId = (Integer) request.getAttribute("userId");

    int pageSize = 20;
    List<Photo> photos = photoMapper.findPage(userId, lastId, pageSize + 1);

    boolean hasMore = photos.size() > pageSize;
    if (hasMore) {
        photos = photos.subList(0, pageSize);   // 丢掉第 21 条
    }

    Map<String, Object> data = new HashMap<>();
    data.put("list", photos);       // Photo 实体需含 id 字段，行内必须带出 id
    data.put("hasMore", hasMore);
    return Result.ok(data);         // 统一包络 { code:0, message:"success", data:{ list, hasMore } }
}
```

**Mapper 接口**（`PhotoMapper.java`）：

```java
List<Photo> findPage(@Param("userId") Integer userId,
                     @Param("lastId") Integer lastId,
                     @Param("limit") int limit);
```

**SQL**（`PhotoMapper.xml`）：

```xml
<select id="findPage" resultType="com.example.entity.Photo">
    SELECT id,
           `_key`      AS `key`,
           user_id     AS userId,
           url,
           name,
           size,
           created_at  AS createdAt
    FROM photos
    WHERE user_id = #{userId}
    <if test="lastId != null">
        AND id &lt; #{lastId}
    </if>
    ORDER BY id DESC
    LIMIT #{limit}
</select>
```

实现要点：

| 要点 | 说明 |
| --- | --- |
| `lastId` 可空 | 不传 = 第一页；用 `<if>` 动态拼 `AND id < #{lastId}` |
| `ORDER BY id DESC` | 每页内部 id 降序，最新在前；**不要用 created_at 排序**（LocalDate 只到天，同日多图顺序不稳） |
| `LIMIT #{limit}` 传 21 | Controller 传 `pageSize + 1`，SQL 不管 hasMore 逻辑 |
| 列名显式别名 | `_key`→`key`、`user_id`→`userId`、`created_at`→`createdAt`，不依赖驼峰自动映射（`_key` 前导下划线自动映射不可靠） |
| 索引 | 建议 `ALTER TABLE photos ADD INDEX idx_user_id (user_id, id);` |
| Photo 实体 | `private Integer id;` 字段必须有（上传接口可以不返回 id，**列表必须返回**） |

#### 3.10.6 前端行为对照（字段缺失时会怎样）

| 后端返回形态 | 前端表现 |
| --- | --- |
| `data.hasMore=true` 且行带 `id` | ✅ 按钮显示，点击追加下一页，末页自动隐藏 |
| `hasMore` 缺失或恒为 `false` | **按钮永不出现**（你当前遇到的现象即此） |
| `hasMore=true` 但行缺 `id` | 按钮显示，但点击时无游标 → 按钮隐藏、不加载 |
| `hasMore=true` 但后端忽略 `lastId` | 点击后列表出现**重复**图片 |
| `data` 直接是数组（无包络对象） | 相册网格空白（前端读不到 `list`/`hasMore`） |
| 行是 snake_case（`_key`/`user_id`） | ✅ 兼容，前端 `normalizePhoto` 自动转 camelCase |

| 401 | token 缺失 / 无效 / 过期 |
| 404 | 资源不存在或不属于当前用户 |
| 500 | 未捕获异常，message 固定 `服务器内部错误`（不暴露堆栈） |
